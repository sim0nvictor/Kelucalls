# FIX-006 - Stable Avatar and Token Logo Storage

## Problem

Channel avatars and token logos could disappear in production because permanent database fields depended on external image URLs.

## Root cause

Telegram Bot API `getFile` URLs are temporary and contain the bot token. DexScreener image URLs are external CDN links and are not a reliable permanent asset store.

## Solution

Kelucalls now uses `workers/asset-store.js` for trusted server and worker flows:

1. Resolve the external image at runtime.
2. Download and validate the image bytes.
3. Upload with deterministic paths and upsert replacement to Supabase Storage.
4. Persist only the stable public Storage URL in `channels.avatar_url` or `tokens.logo_url`.

The channel sync and token backfill workers are rerunnable, rate-limited, retry transient failures, and isolate individual item failures. New channel discovery and token ingestion use the same resolver where an external image is available.

## UI behavior

`ChannelAvatar` falls back to channel initials. `TokenAvatar` falls back to token symbol initials. Both handle missing and failed images without displaying a broken-image state and lazy-load by default.

## Why it matters

- Improves production reliability.
- Removes bot-token-bearing URLs from permanent asset storage.
- Reduces external runtime image dependencies.
- Keeps UI behavior consistent across web surfaces.
- Avoids eager loading every channel or token image.
- Provides reusable infrastructure for future mobile, PWA, and notification surfaces.

## Database and deployment

No new table or column is required. `supabase/migrations/017_asset_storage.sql` creates the public-read `assets` bucket with trusted-worker-only writes. The migration must be applied before the workers are deployed, and existing rows should be repaired by running the avatar and logo backfills.
