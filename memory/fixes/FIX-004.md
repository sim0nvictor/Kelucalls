# FIX-004 - Daily Research Worker Report Type Regression

**Status:** Active

**Introduced:** 2026-08-29

**Fixed:** 2026-08-31

**Area:** Worker

---

## Symptom

`npm run typecheck` failed in `workers/daily-research.ts` because the awaited Daily Research report was typed as `ReturnType<typeof generateDailyResearchReport>`, which is `Promise<DailyResearchReport>`.

TypeScript then treated the local `report` value as a Promise instead of the generated report object passed to validation, snapshot persistence, and draft article creation.

---

## Root Cause

`generateDailyResearchReport()` is async. `ReturnType<typeof generateDailyResearchReport>` captures the unresolved Promise type, not the awaited report value.

The previous workaround used casts and non-null assertions around the downstream calls, which hid the intended runtime shape instead of proving it.

---

## Fix

`workers/daily-research.ts` now imports the domain type `DailyResearchReport` from `src/lib/research/types` and stores the generated value as `DailyResearchReport | null`.

After LLM generation, the worker explicitly throws if no report exists before entering validation. That gives TypeScript a real control-flow guard and keeps the runtime failure mode clear.

---

## Verification

- `npm run typecheck`
- `npm run verify:research-generator`
- `npm run verify:research-validator`

All passed after the fix.
