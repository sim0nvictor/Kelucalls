# FIX-005 - Daily Research Validation Contract Drift

## Problem

The daily research worker reaches Gemini successfully, saves the snapshot, and then fails validation on generated reports. The failures are inconsistent: sometimes the model cites unsupplied evidence references, sometimes it emits malformed numeric strings, and sometimes it produces a valid-looking sentence that the validator treats as an unverified fact.

## Root cause

There were two independent issues in the same pipeline:

1. Evidence contract drift between the generator and the validator.
   - The generator canonicalizes evidence paths with a normalizer that accepts patterns such as `signals[0]`, `signals.0`, `signal_results.signals.0`, and `research_snapshot.newsData.items[8]`.
   - The validator used a separate path normalizer and a narrower whitelist, so the same claim could be accepted by one layer and rejected by another.
   - This caused intermittent `unsupplied evidence` failures even when the references were structurally valid in the actual snapshot.

2. Numeric validation was too eager.
   - The validator scanned all numeric-looking phrases in prose and treated them as factual claims requiring direct snapshot support.
   - This produced false positives for incidental prose like `2.0`, `$183.50`, `$500`, and malformed comma patterns such as `$88,438,579,86,`.
   - The result was a validator that was effectively evaluating narrative style instead of source-backed claims.

## Why it matters

This is the core reason the pipeline kept failing even after the provider and news collection layers had already been made more resilient:

- data collection was not the main bottleneck,
- the snapshot itself was mostly usable,
- the report generator and validator were disagreeing about what counted as valid evidence,
- and the validator was rejecting unsupported-but-incidental numbers instead of only truly unsupported numeric claims.

## Solution

- Keep the evidence path contract aligned between the generator and the validator.
- Normalize `signals`, `signal_results`, and bracket notation in a single canonical way.
- Reject malformed numeric tokens before treating them as source-backed facts.
- Continue requiring evidence-backed data without disabling numeric validation entirely.
- Keep provider failures isolated so GDELT 429 or other provider outages degrade the snapshot instead of crashing the whole run.

## Verification

Verified behavior:

- The validation regression script passes for the malformed numeric patterns and evidence-normalization cases.
- The real worker still shows a remaining live validation failure in the end-to-end path because the generator output is still not fully aligned with the validator's strict source matching logic.
- GDELT failures remain isolated and are not destroying the worker; they are treated as degraded provider failure, not a complete snapshot failure.

## Status

This issue is partially resolved in the validation layer but not yet fully complete in the live worker. The root cause has been diagnosed and narrowed to evidence-path contract drift plus overly aggressive numeric validation logic.
