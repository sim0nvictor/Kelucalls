# FIX-005 - Repository ESLint Cleanup

**Status:** Active

**Introduced:** Before 2026-09-03

**Fixed:** 2026-09-03

**Area:** Web app, Insights, token market, research pipeline

---

## Symptom

`npm run lint` reported 13 errors and one warning across authentication routes, Insights pages, chain icons, sharing controls, live token components, and research helpers.

The failures included unused parameters and helpers, an unnecessary mutable binding, unescaped JSX text, and synchronous state updates inside effects.

---

## Root Cause

Several small issues accumulated across unrelated features. React's hooks lint rules also identified state resets and initialization work that did not need to run synchronously inside effects.

The chain icon fallback reset used an effect even though the failed URL itself could identify when the fallback should apply. Browser-only sharing state was also synchronized after mount instead of being exposed through React's external-store hydration contract.

---

## Fix

- Removed unused route parameters and research helpers.
- Changed the immutable Markdown-processing binding to `const`.
- Escaped user-facing JSX punctuation.
- Tracked the failed chain-icon URL instead of resetting state in an effect.
- Switched chain icons to unoptimized `next/image` rendering while preserving runtime URLs and the initial fallback.
- Used `useSyncExternalStore` for hydration-safe browser share URL and native-share capability values.
- Deferred the initial live-price request to the timer callback and initialized clocks through lazy state initializers.
- Added pull-request lint verification so regressions are caught automatically.

No ESLint rules were disabled or weakened.

---

## Verification

- `npm run lint`
- GitHub pull-request lint check
- Vercel preview build

The lint check completed successfully with no reported errors or warnings after the final chain-icon update.
