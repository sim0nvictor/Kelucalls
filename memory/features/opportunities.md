## Opportunities (KeluScore intent engine)

**What it is:** `/opportunities` — tokens the system flags as worth a closer look right now, based on a composite "KeluScore" (0–100, graded A–D) rather than just raw call counts.

**How it works, end to end:**
1. `workers/intent-engine.js` runs every ~30 minutes, reading `calls`, `call_metrics`, `channel_stats`, and `tokens` for everything called in the last 30 days.
2. For the busiest tokens (top 150 by recent call volume), it also pulls fresh external data from Dexscreener (liquidity, 24h volume, price change, website/social presence) — the same API `price-update.js` already calls, just reading fields that worker discards.
3. `computeKeluScore()` (pure math, no I/O) blends eight weighted sub-scores into one number:
   - **Conviction** (28%) — quality of the channels calling it, weighted by how many independent channels agree
   - **Momentum** (24%) — is call activity *accelerating* relative to this token's own normal pace, not just high in absolute terms
   - **Breadth** (16%) — how many independent channels, not just one channel spamming
   - **Performance** (16%) — historical win rate and average peak multiple on this specific token
   - **Freshness** (8%) — exponential decay, 48-hour half-life, so stale winners fall off the board
   - **Liquidity** (4%), **Marketing** (2%), **Community** (2%) — external signals, each of which is `null` (not zero) until real data exists for that token
4. The result is stored in `intent_scores` along with plain-English **signals** (e.g. "Only one channel has called this — single-source calls carry more risk") and **recommendations** (e.g. "Coverage is concentrated in very few channels. Verify independently before acting"), both generated by rule-based logic, not an LLM.
5. `intent-panel.tsx` on the frontend only ever reads this finished row — the score is never computed at page-load time.

**Design principle worth remembering:** a sub-score being unavailable (e.g. no Dexscreener liquidity data yet) is excluded from the composite entirely rather than dragging the score toward zero — this "null means unknown, not bad" rule is enforced independently at the database layer, the scoring math, and the LLM summary prompt (see Feature 5), because it's easy to accidentally violate at any one of those layers alone.
